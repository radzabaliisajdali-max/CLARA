# CLARA: план завершения рабочего кабинета

Дата: 06.10.2026. Это план следующих изменений, а не перечень уже выполненных функций. Составлен по текущему коду и требованиям Али. Главный критерий: человек видит свою задачу, выполняет действие и получает проверяемый результат.

## Исходное состояние

Есть сервер, авторизация, товары и варианты, складские документы, базовый производственный цикл, история и экспорт. Меню сгруппировано, производство разделено вкладками. Чтение рекламы реализовано, но с реальным кабинетом WB пока не проверено. FBS, FBO, маркировка, полноценные финансы, аналитика, SEO и акции требуют реализации. Текущие введённые товары и производство сохраняются при всех обновлениях.

## 1. Постоянное меню

| Раздел | Отдельные рабочие страницы |
| --- | --- |
| Сегодня | Мои задачи, сроки, ошибки синхронизации, документы с проблемами |
| Товары | Каталог; карточка модели; варианты; себестоимость; импорт |
| Производство | Планы; крой; пошив; контроль качества; упаковка; выпуск; исполнители |
| Наш склад | Остатки; приёмки; резервы; перемещения; инвентаризация; журнал документов |
| Wildberries | FBS-заказы; сборка; поставки FBS; FBO/FBW; остатки WB; возвраты |
| Маркировка | Коды и привязки; документы; подтверждения; ошибки |
| Продвижение | Реклама; акции; SEO и ключевые слова |
| Аналитика | Продажи и воронка; ABC; прибыльность; конкуренты; сравнение карточек; потребность в производстве |
| Финансы | Доходы и расходы; себестоимость; выплаты; обязательства; платёжный календарь |
| Настройки | Подключения; пользователи; права; печать; справочники; аудит; резервные копии |

Владелец видит весь доступный функционал. Оператор — только разрешённые операции. Проверка прав выполняется сервером, а не только скрытием кнопок. Список швей не равен списку пользователей системы.

Разделы, которые ещё разрабатываются, показываются в отдельном списке «План развития», а не как работающие пункты рабочего меню. Готовый модуль без подключения показывает состояние «Не подключено» и реальную инструкцию настройки.

## 2. Единое поведение всех экранов

- Заголовок отвечает на вопрос «Где я?», краткое пояснение — «Что здесь делать?».
- Сначала список записей, затем поиск и фильтры; создание и редактирование открываются отдельно.
- Одна основная кнопка на экране. Второстепенные действия находятся в строке или карточке записи.
- Нажатие на строку открывает подробности, связанные документы и историю. Возврат сохраняет фильтры, страницу таблицы и позицию.
- Страница, вкладка и фильтры имеют адрес: обновление браузера и кнопка «Назад» не сбрасывают рабочий контекст.
- Для изменения указывается конкретный объект и количество. Кнопки называются «Принять 12 шт.» или «Передать в пошив», а не просто «Выполнить».
- Во время запроса виден ход операции. Повтор защищён на сервере; при ошибке форма и безопасный ключ повтора сохраняются.
- После сохранения показываются номер документа, итог и ссылка «Открыть документ»; данные перечитываются с сервера.
- Недоступное действие объясняет причину: нет прав, недостаточно остатка, неверный этап, нет подключения. Цвет дополняется текстом.
- Для массового действия видны количество выбранных записей и результат по каждой строке. Частичный успех не маскируется общим сообщением.
- Экспорт выгружает именно выбранный состав и фильтры, указывает дату, источник и единицы измерения.
- Пустой список, загрузка, отсутствие подключения, устаревший ответ и ошибка — разные состояния.
- На узком экране меню сворачивается, длинные таблицы имеют понятную прокрутку, основное действие доступно без поиска по всей странице.

## 3. Назначение основных кнопок

| Экран / кнопка | Что открывает или изменяет | Проверяемый результат |
| --- | --- | --- |
| Каталог / Добавить модель | Отдельная форма артикула и названия | Модель появилась, склад не изменился |
| Карточка / Добавить вариант | Цвет, размер, GTIN и себестоимость | Уникальный GTIN связан с конкретным вариантом |
| Импорт / Проверить файл | Предпросмотр, дубли, ошибки и состав импорта | Ничего не записано до подтверждения |
| План / Создать план | Варианты, количества и срок | План создан, готовый склад не увеличился |
| План / Зафиксировать крой | Крой по выбранным строкам, ткань, исполнитель | Фактический крой отделён от плана |
| Крой / Передать в пошив | Доступное количество и выбранная швея | Выдача зафиксирована, повтор её не дублирует |
| Пошив / Принять на контроль | Количество от выбранного исполнителя | Остаток у исполнителя уменьшился на принятую величину |
| Контроль / Передать на упаковку | Годное количество; брак оформляется отдельно | Раздельные результаты контроля |
| Упаковка / Выпустить на склад | Подтверждение упакованных изделий | Один документ выпуска и связанная складская приёмка |
| Приёмка / Подтвердить приёмку | Проверенные сканы или введённые количества | Неизвестный GTIN отклонён; склад изменён документом |
| Резервы / Зарезервировать | Вариант, количество и основание | Доступный остаток уменьшился, физический сохранён |
| Инвентаризация / Провести расхождения | Факт, расчёт разницы и обязательная причина | Корректировка владельцем, без прямого редактирования остатков |
| Документ / Исправить | Компенсация с причиной и проверкой зависимостей | Исходная история сохранена, итог корректен |
| FBS / Обновить заказы | Синхронизация доступных данных WB | Видны новые данные, время и ошибки; дубли не созданы |
| FBS / Начать сборку | Рабочее место выбранного заказа | Видны товар, вариант, количество, проверяемые шаги |
| Сборка / Проверить скан | Сопоставление с заказом и привязка маркировки при необходимости | Чужой вариант или код не принимается |
| Сборка / Печать этикетки | Предпросмотр и отправка на настроенную печать | Повтор печати не повторяет складскую операцию |
| Поставка / Передать WB | Явное подтверждение состава и допустимого действия | Внешний ответ и внутреннее движение согласованы; ошибка доступна для повтора |
| Маркировка / Проверить статус | Чтение внешнего состояния | «Отправлено» и «Подтверждено» показаны отдельно |
| Возврат / Принять возврат | Проверка товара, качества, кода и направления | Годное, брак и карантин разделены |
| Реклама / Обновить отчёт | Кампании и выбранный период | Метрики с источником и свежестью, без изменения бюджета |
| Акции / Рассчитать участие | Условия акции, цена, расходы, налог, целевая маржа | Прибыль, предел скидки, минимальная цена и объяснение |
| SEO / Подготовить предложение | Анализ ключей и проект изменений карточки | Предложение сохранено; публикация отдельным действием |
| Аналитика / Создать рекомендацию | Расчёт с исходными данными и допущениями | Объяснимая рекомендация и ожидаемый эффект |
| Подключения / Проверить доступ | Запрос к сервису с необходимыми правами | Проверенные возможности и понятная ошибка, без вывода секретов |

Проверка реального физического выхода этикетки зависит от принтера и его программного обеспечения: получение файла или отправка в очередь не выдаются за подтверждённую печать.

## 4. Главные границы учёта

- План, крой, незавершённое производство, готовое на собственном складе, резерв FBS, путь, WB и брак не суммируются как один доступный остаток.
- Резерв FBS входит в физический склад. Точка списания при отгрузке задаётся один раз и проверяется вместе с процессом передачи.
- Производственная упаковка и упаковка заказа FBS — разные страницы и документы.
- Финансы хранят денежные операции; аналитика читает их и показывает расчёты. Себестоимость имеет один источник с историей, доступный из карточки товара.
- ABC по выручке/прибыли, аудит фотографий и характеристик, SEO и A/B-эксперименты — отдельные инструменты.
- Данные своего кабинета и оценки конкурентов имеют разные подписи и источники. Закрытая статистика конкурентов не считается доступной через собственный токен WB.
- Выгода акции рассчитывается после расходов, с явной налоговой базой; 6% — исходная настройка, а не автоматически верный налог для любой операции. Неизвестные расходы не заменяются нулями. Дополнительно оценивается необходимый рост объёма, а не только прибыль с единицы.
- Бизнес-событие возврата и юридическое действие с кодом маркировки связаны, но не тождественны. Правила, сроки и допустимые API проверяются по официальным источникам перед разработкой.

## 5. Очерёдность реализации и приёмка

### Этап 1. Завершить понятный интерфейс готовых функций

Постоянные адреса, список → карточка → действие, отдельные приёмки/резервы/корректировки, устранение общей формы «резерв или корректировка». Разделить производство по реальным этапам вместо универсальной формы передачи. Сохранить текущие данные и проверки API.

Приёмка: владелец и оператор проходят товар → план → крой → пошив → контроль → упаковка → склад. Проверяются возврат назад, обновление страницы, сканер, ошибки и мобильный экран. Каждая видимая кнопка имеет проверяемый результат.

### Этап 2. Подключения и настоящие FBS-заказы

Проверить официальные API и минимальные права. Добавить безопасную настройку подключения, синхронизацию с пагинацией и лимитами, сопоставление вариантов, резервирование, контроль отмен и фоновых ошибок. После чтения — реализовать доступные операции сборки, поставок и печати.

Приёмка: один заказ проходит полный цикл; повтор синхронизации и отправки не создаёт дубль, конкурентная сборка не списывает лишнее, отмена освобождает соответствующий резерв. Реальный доступ проверяется отдельно от тестовых ответов.

### Этап 3. Маркировка и возвраты для FBS, затем FBO/FBW

До готовности обязательных проверок маркировки реальный маркируемый заказ нельзя считать полностью обработанным. Реализовать привязку кодов, очередь документов, проверку подтверждений и исправление ошибок. Возвраты принимать отдельно от повторного допуска к продаже. После этого завершить отгрузки FBO/FBW, товар в пути и сверку приёмки WB.

Приёмка: неверный/повторный код, отмена, возврат годного изделия, брак, отказ внешнего сервиса, частичная приёмка WB. Ключи подписи и токены не попадают в журнал и браузерный ответ.

### Этап 4. Фактические финансы и акции

Загрузить и сверить продажи, возвраты, комиссии, логистику, эквайринг, хранение, штрафы, рекламу и выплаты. Подключить себестоимость и налоговые настройки. На этой основе реализовать таблицу акций и сценарии цены. Пока полной экономики нет, разрешён явно помеченный расчёт с проверенными ручными входными данными.

Приёмка: расчёты сходятся с исходными операциями, нет двойного вычитания комиссий, перечисления отделены от прибыли. Проверены прибыльная акция, убыток, предел скидки и недостаток данных. Вступление в акцию и изменение цены требуют отдельного подтверждения.

### Этап 5. Реклама, внутренняя аналитика, SEO и конкуренты

Проверить имеющееся чтение рекламы на реальном кабинете. Связать рекламные метрики с воронкой и фактической экономикой. Реализовать ABC, дни запаса, потребность по размерам, подбор ключей и сравнение карточек. Для внешних данных сначала определить законный источник и его ограничения, затем подключать сбор.

Приёмка: каждый показатель раскрывается до источника, периода и формулы. Оценки конкурентов отделены от фактов. Рекомендация не предлагает рост рекламы или выпуска без проверки экономики и доступных средств.

### Этап 6. Агенты и подготовка рабочего запуска

Агенты используют те же API, права и документы, что пользователь. Первый режим — сбор и рекомендации. Изменения цены, рекламы и публикация карточки показывают предварительный результат и выполняются после подтверждения. Журнал хранит входные данные, решение, автора и проверку результата.

Приёмка запуска: резервное копирование и восстановление, миграции с сохранением данных, разграничение прав, повтор и потеря ответа, частичный отказ интеграции, инструкция сотруднику. Размещение и эксплуатационные настройки выбрать перед развёртыванием.

## 6. Когда раздел считается готовым

Для каждой кнопки составить реестр: роль → условия доступности → действие → серверная проверка → результат → ошибка → безопасный повтор → история. Проверить основные пользовательские маршруты, а не только наличие обработчиков. Для интеграций отдельно помечать: реализовано; проверено тестами; проверено на реальном кабинете. Следующий этап начинается после проверки предыдущего; наличие макета не означает готовность операции.
