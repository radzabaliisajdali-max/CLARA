# Единый кабинет и подключение WB

06.10.2026. Реализовано: кнопка подключения с главной страницы владельца, единая форма API-токена, серверное шифрование AES-256-GCM, общий источник ключа для адаптеров, использование рекламой без перезапуска. Оператор не может менять ключ. В API, аудит и ответы ключ не попадает. Сохранение не означает проверку прав или синхронизацию всех модулей.

## Настройка сервера

Один раз создать случайный 32-байтовый ключ шифрования, записать его в серверный `.env` как `WB_TOKEN_ENCRYPTION_KEY` (64 шестнадцатеричных символа). Пример команды есть в `.env.example`. Этот ключ сохранять отдельно от резервной копии БД; потеря ключа потребует повторно подключить WB. Не менять его при обычном перезапуске. Для рабочего размещения использовать HTTPS и защищённое хранение серверных секретов.

После запуска владелец открывает «Рабочий день → Подключить / настроить Wildberries», вставляет WB-токен в форму и сохраняет. Новые запросы рекламы используют его автоматически. При замене старый кэш отделяется по хешу ключа. Серверные `WB_API_TOKEN` и прежний `WB_ADS_TOKEN` поддержаны как резервная конфигурация, если в БД ещё нет подключения. Отдельный ключ в каждом разделе не требуется.

Текущая версия рассчитана на один кабинет WB. Не менять токен на токен другого продавца для объединения магазинов: многокабинетный учёт требует отдельной реализации.

## Следующие законченные операции

1. Общая диагностика категорий доступа и очередь синхронизации: статус по модулю, время, ошибка, безопасный повтор.
2. Карточки WB и сопоставление вариантов: предварительная проверка GTIN, без автоматической перезаписи наших товаров и себестоимости.
3. Заказы FBS и отдельный снимок остатков WB; собственные остатки меняются только документами CLARA.
4. Продажи, финансовые отчёты и воронка; сверка исходных сумм.
5. Акции с расчётом допустимой скидки; SEO по доступным запросам и характеристикам.
6. Конкуренты: отдельный разрешённый источник данных с обозначением оценок и ограничений. Собственный токен не даёт закрытую статистику чужих кабинетов.

Права токена зависят от категорий API: [официальная документация WB](https://dev.wildberries.ru/docs/openapi/api-information). Настраивать только необходимые реализованным операциям права. Честный знак имеет отдельную авторизацию. Общая форма подключения не заменяет реализацию каждого адаптера.

## Проверено

15 локальных проверок: существующий склад/производство, шифрование ключа, отсутствие открытого ключа в резервной копии и ответах, запрет изменения оператором, использование общего ключа рекламным адаптером. WB в тесте заменён контролируемым ответом. Реальный пользовательский токен не вводился и живые данные WB ещё не загружались.

## Каталог и экран по размерам

Добавлена загрузка POST /content/v2/get/cards/list с пагинацией по 100 карточек, withPhoto=-1, паузой между страницами и сохранением полного ответа карточек. После сохранения ключа интерфейс запускает загрузку. До завершения всех страниц существующий каталог не заменяется. Корзина WB этим методом не возвращается; максимум текущего синхронного запуска — 10 000 карточек.

Модели и однозначные варианты импортируются без перезаписи существующих цен, себестоимости или остатков. Несколько штрихкодов у одного размера, несовместимый формат, неизвестный цвет и конфликты показываются для проверки; исходная карточка сохраняется целиком. Повторная загрузка не создаёт дублей. Снимки разделены по ключу подключения.

«Товары → Товары WB по размерам» показывает артикул, размер, все штрихкоды, связанные собственные остатки и резерв. Колонки остатков WB, скорости продаж и потребности пока показывают «Нет данных»; отчёты для их расчёта ещё не подключены. Планируемая потребность должна учитывать историю по размеру, доступный запас, путь, незавершённое производство, срок выпуска и целевой запас; простое умножение темпа без этих данных не выдавать за окончательный план.

Источник: https://dev.wildberries.ru/openapi//work-with-products . В локальном тесте проверены импорт и повтор без дублей; живой WB не проверен.
