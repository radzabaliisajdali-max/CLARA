# Акции WB: требования к оценке участия

Добавлено по запросу Али 6 октября 2026. Статус: проект модуля, автоматическая загрузка акций и расчёт рекомендаций ещё не реализованы.

Раздел «Акции WB» в аналитическом центре. В списке товаров отдельная колонка «Акция»: название, период, участие и итог оценки, с переходом к подробному расчёту.

## Таблица решения

Товар / цвет / размер → акция и сроки → текущая цена продавца → требуемая цена и скидка → себестоимость → расходы → прогноз прибыли на единицу → прогноз маржи → минимальная цена для заданной маржи → оценка → объяснение.

Оценки: «Проходит ваш порог», «Ниже целевой маржи», «Убыток», «Недостаточно данных». Положительная прибыль на единицу не означает, что акция увеличит общую прибыль: отдельно показывать сценарий объёма, требуемый рост продаж относительно обычной цены, доступный запас и возможность производства. Не обещать рост трафика или заказов без данных.

## Расчёт

Разделять цену продавца, цену для покупателя после скидок WB и базу расчёта перечисления. planPrice и planDiscount из API сохранять вместе с описанием их смысла; не применять скидку повторно. СПП не считать автоматически расходом продавца.

Расходы: себестоимость, комиссия WB, логистика, эквайринг, хранение, реклама, возвраты и прочие относимые удержания, налог. Если исходная сумма «к перечислению» уже учитывает комиссию/эквайринг, не вычитать их второй раз. Расходы по отчётам связывать с конкретным товаром и периодом. Исторические удельные расходы, перенесённые в будущую акцию, помечать допущением; заданные вручную значения — отдельным источником.

По умолчанию ставка налога 6%, но налоговая база отображается явно и не приравнивается к прибыли. Будущий результат — прогноз, а не фактическая прибыль. При неизвестных обязательных расходах выводить «Недостаточно данных», не подставлять нули. Минимальную цену и предельную скидку рассчитывать с учётом зависимости процентных расходов от цены; нельзя просто складывать фиксированные расходы. Целевая маржа задаётся владельцем, универсальный порог выгодности не придумывается.

## API и границы

Официальная документация WB описывает календарь акций (категория токена «Цены и скидки»):

- GET /api/v1/calendar/promotions — список и сроки;
- GET /api/v1/calendar/promotions/details — сведения об акции;
- GET /api/v1/calendar/promotions/nomenclatures — участвующие/доступные товары, текущие и плановые цены/скидки.

Базовый адрес: https://dp-calendar-api.wildberries.ru . Последний метод не предназначен для автоакций; их доступность проверяется отдельно, допускается проверяемый импорт условий из отчёта WB. Обрабатывать пагинацию, права доступа, платность метода, устаревшие данные и лимиты. Перед разработкой повторно проверить актуальные схемы.

Первый режим — чтение, сравнение и рекомендация. Запись товара в акцию и изменение цены не выполняются автоматически. Будущее подтверждение показывает товар, старую/новую цену, акцию и расчёт. Участие считается подтверждённым только после проверки результата WB.

Источник: https://dev.wildberries.ru/en/docs/openapi/promotion?locale=ru%2F (Promotions Calendar), проверен 06.10.2026.

## Проверка

Примеры: прибыльная цена, убыток, нулевая маржа, недостающая себестоимость, разные размеры с разной себестоимостью, расходы уже учтены в перечислении, СПП, процентные расходы, возвраты, ошибка доступа API, автоакция без списка товаров. Каждый результат должен раскрываться до исходных сумм и формулы.
