# Производство: базовый цикл

1. Создайте модель и варианты с реальными GTIN в «Товарах».
2. В «Производстве» выберите цвет/размер, количество и срок. Количества задаются вручную: продажи WB ещё не подключены.
3. Создайте отдельный крой по плану: дата, количество, общий расход ткани в килограммах, ответственный. Программа присваивает номер и рассчитывает кг на изделие. Для превышения плана обязательна причина; частичные крои разрешены.
4. Добавьте швею. Выберите номер кроя и «Выдать крой швее».
5. По факту пошива выберите ту же швею и «Принять пошив на контроль». Нельзя сдать больше выданного этой швее.
6. После контроля передайте годные изделия в упаковку, брак — отдельной операцией с причиной.
7. После упаковки подтвердите «Упаковано → принять на наш склад». Только эта операция увеличивает физический остаток. Не проводите затем повторную обычную приёмку тех же изделий.

Повторная отправка формы после потери связи безопасна. Операция, складское движение, аудит и ответ идемпотентности записываются одной транзакцией. Параллельные выдачи одного кроя не могут превысить его остаток.

Владелец отменяет переход в истории производства с указанием причины. Если изделия уже переданы дальше, сначала отмените следующие переходы. Отмена готовности также снимает приход на склад и отклоняется при нехватке доступного остатка. Отдельно отменять связанный складской документ нельзя.

Excel в разделе содержит партии, расход и остатки по этапам. Резервная копия включает планы, крои, швей и историю. Для восстановления используйте ту же версию схемы; копию V5.0 сначала восстанавливайте кодом V5.0, затем обновляйте приложение, которое применит миграцию 002.

## Границы этой версии

- Один план и один крой относятся к одному цвету/размеру. Общая раскладка нескольких размеров с единым расходом ткани — следующий шаг. Не вводите весь расход одной раскладки повторно для каждого размера.
- Планы и записи кроя после сохранения неизменяемы. Отмена переходов реализована; исправления исходного плана/кроя отдельными документами ещё предстоит добавить.
- Брак фиксируется на контроле по партии; персональная атрибуция брака швее и оплата труда пока не реализованы.
- Отдельного склада ткани, норм, недельных отчётов и рекомендаций производства по реальным продажам пока нет.
- Экран localhost в ходе разработки использует изолированную тестовую базу. Рабочая база Docker создаётся пустой.
