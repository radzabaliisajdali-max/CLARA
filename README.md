# CLARA V5 — сервер, товары и собственный склад

Продолжение V4.1: русский интерфейс и рабочие данные в PostgreSQL. Тестовые записи не загружаются при старте. Исторические файлы V4.1 в корне оставлены для сравнения; сервер публикует только `public/`.

## Запуск на Windows

1. Установите и запустите Docker Desktop с Linux containers.
2. Скачайте эту ветку, откройте PowerShell в папке CLARA.
3. Выполните `Copy-Item .env.example .env`.
4. Откройте `.env` локально. Задайте свои `POSTGRES_PASSWORD`, `OWNER_LOGIN`, `OWNER_PASSWORD` (минимум 12 символов). Не отправляйте пароли в чат. Compose передаёт пароль БД отдельно, через PGPASSWORD; DATABASE_URL для Docker не используется.
5. Выполните `docker compose up --build -d`.
6. Откройте **http://localhost:3000**, войдите с указанным логином и паролем.

Владелец создаётся только в пустой базе. Изменение `.env` не сбрасывает пароль существующего пользователя. Роль, пароль и активность меняются в разделе «Пользователи»; изменение отзывает сессии пользователя.

Compose публикует порт только на 127.0.0.1. Для рабочего сервера нужны HTTPS, точный `APP_ORIGIN`, `COOKIE_SECURE=true`, резервные копии. Текущий Compose предназначен для локальной проверки.

## Первый рабочий день

1. В «Товары» создайте модель и варианты **цвет + размер + GTIN**.
2. Либо в «Импорт V4.1» отметьте проверенные модели. Варианты создайте вручную: старые штрихкоды не связаны однозначно с размерами. Остатки, цены и коэффициенты не импортируются.
3. В «Приёмка» сканируйте GTIN: повторный скан прибавляет 1, количество можно исправить вручную.
4. Нажмите «Подтвердить приёмку». В «Наш склад» появятся физическое и доступное количество.
5. Внутренний резерв FBS уменьшает доступный остаток, сохраняя физический. Публикация на WB ещё не подключена.
6. Ошибки исправляются корректировкой с причиной либо через «Движения → Отменить». Исходная запись сохраняется. Отмена невозможна, если приводит к нехватке остатка или затрагивает резерв.

В пути, WB и брак учитываются отдельно. Их начальная сверка доступна владельцу как корректировка; автоматические FBO-перемещения — следующий этап. Неизвестная себестоимость показана как «Нет данных», а не ноль. GTIN — строка с ведущими нулями; форматная проверка не заменяет регистрацию в ЧЗ.

## Резервная копия и восстановление

Копия сохраняет согласованный снимок моделей, пользователей с хешами паролей, документов, истории, остатков и ключей идемпотентности. Сессии не копируются. Храните копии в защищённом месте.

```powershell
docker compose exec app node dist/backup.js save /tmp/clara-backup.json
New-Item -ItemType Directory -Force backups
docker compose cp app:/tmp/clara-backup.json ./backups/clara-backup.json
```

Для следующей копии используйте новое имя: существующий файл не перезаписывается.
Восстанавливайте в **новую пустую БД**:

```powershell
docker compose exec db createdb -U clara clara_recovery
docker compose cp ./backups/clara-backup.json app:/tmp/restore.json
docker compose exec -e PGDATABASE=clara_recovery app node dist/backup.js restore /tmp/restore.json
```

После проверки укажите `PGDATABASE: clara_recovery` для app в Compose и пересоздайте app. Исходная база остаётся доступной. Версия кода и миграций должна соответствовать копии; несовместимая версия или непустая целевая база отклоняются. После восстановления войдите заново.

На другой машине сначала запустите только `docker compose up -d db`, затем восстановите копию через `docker compose run --rm --no-deps` со смонтированным файлом копии; не запускайте приложение/bootstrap до восстановления.

## Разработка и тесты

Node.js 22+, pnpm 11.19.0, PostgreSQL 17. Версии зависимостей зафиксированы в pnpm-lock.yaml.

```sh
corepack enable
corepack prepare pnpm@11.19.0 --activate
pnpm install --frozen-lockfile
pnpm build
pnpm test
pnpm exec playwright install chromium
pnpm test:ui
```

Без `TEST_DATABASE_URL` тесты поднимают встроенный временный PostgreSQL. С `TEST_DATABASE_URL` используют указанный тестовый сервер, создают отдельную случайно названную схему и удаляют её после проверки. Нужны права CREATE SCHEMA. Не используйте production-сервер. На Windows выбирайте короткий путь, например `C:\work\CLARA`, из-за ограничения длины путей PostgreSQL.

Без Docker: задайте DATABASE_URL, OWNER_LOGIN, OWNER_PASSWORD, APP_ORIGIN в окружении, выполните `pnpm build`, `pnpm start`. Для чтения .env напрямую: `node --env-file=.env dist/server.js`. При использовании DATABASE_URL спецсимволы пароля URL-кодируются. Миграции применяются до старта сервера под блокировкой, с проверкой контрольных сумм.

Готовы: вход/роли, модели/варианты, приёмка, внутренние резервы, корректировки, отмена, аудит, сверка и восстановление остатков, Excel, импорт моделей, копия/восстановление БД, тесты и CI.

Следующие этапы: производство/крой/пошив, официальный WB API и стикеры, печать, FBO, ЧЗ/возвраты, фактические финансы и аналитика. Эти разделы явно показывают отсутствие подключения. Автоматических изменений цен и скидок, фиктивных заказов и прибыли нет.
